# Secret Management Strategy

This project utilizes a consolidated secret management strategy to minimize duplication and enhance security. We distinguish between **Infrastructure Secrets** (used by CI/CD pipelines) and **Application Secrets** (used by the running application).

## Overview

*   **GitHub Secrets**: Store only the credentials required for the GitHub Actions runner to authenticate with Google Cloud and Firebase.
*   **Google Secret Manager**: Stores all runtime configuration and sensitive keys (Database credentials, API keys, Firebase config).

## GitHub Secrets (Infrastructure)

The following secrets must be configured in the GitHub Repository Settings:

| Secret Name | Description | Required For |
| :--- | :--- | :--- |
| `GCP_SA_KEY` | JSON Key for the Service Account used by GitHub Actions. | `deploy.yml` (Auth) |
| `FIREBASE_SERVICE_ACCOUNT_DISCIPLESHIP_JOURNAL` | JSON Key for Firebase Hosting deploy (typically generated by `firebase init hosting`). | `deploy.yml` (Firebase) |
| `GCP_SERVICE_ACCOUNT` | The email address of the Runtime Service Account (attached to Cloud Run). | `deploy.yml` (Cloud Run) |
| `CLOUD_SQL_INSTANCE` | The Cloud SQL connection name (e.g., `project:region:instance`). | `deploy.yml` (Cloud Run) |
| `FIREBASE_PROJECT_ID` | The Project ID (e.g., `discipleship-journal-pwa`). | `deploy.yml` (Config) |
| `GCP_REGION` | The Google Cloud region (e.g., `asia-southeast1`). | `deploy.yml` (Config) |
| `GCP_SERVICE_NAME` | The Cloud Run service name. | `deploy.yml` (Config) |
| `GCP_ARTIFACT_REPOSITORY` | The Artifact Registry repository name. | `deploy.yml` (Config) |

## Google Secret Manager (Application)

The following secrets must be created in Google Secret Manager within the GCP Project. The application fetches these at runtime (Backend) or build time (Frontend).

### Backend Secrets
*Fetched by the Go Backend on startup.*

*   `DB_PASSWORD`
*   `DB_USERNAME`
*   `DB_NAME`
*   `BIBLE_API_KEY`
*   `BIBLE_API_URL`

### Frontend Secrets
*Fetched by GitHub Actions during the build process and baked into the static assets.*

*   `FIREBASE_API_KEY`
*   `FIREBASE_AUTH_DOMAIN`
*   `FIREBASE_STORAGE_BUCKET`
*   `FIREBASE_MESSAGING_SENDER_ID`
*   `FIREBASE_APP_ID`
*   `FIREBASE_MEASUREMENT_ID`
*   `GCP_API_URL` (The public URL of the Backend API)

## IAM Permissions

To ensure this flow works, the following IAM bindings are required:

1.  **GitHub Actions Service Account** (associated with `GCP_SA_KEY`):
    *   Role: `roles/secretmanager.secretAccessor` (To fetch frontend secrets during build).
    *   Role: `roles/run.admin` (To deploy Cloud Run).
    *   Role: `roles/storage.admin` (To push to Artifact Registry).
    *   Role: `roles/iam.serviceAccountUser` (To act as the runtime service account).

2.  **Runtime Service Account** (associated with `GCP_SERVICE_ACCOUNT`):
    *   Role: `roles/secretmanager.secretAccessor` (To fetch backend secrets at runtime).
    *   Role: `roles/cloudsql.client` (To connect to Cloud SQL).
